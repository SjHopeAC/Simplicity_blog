# 第 2 章：分词器学习笔记

> 依据 Datawhale 的[《Diy-LLM》第 2 章：分词器](https://datawhalechina.github.io/diy-llm/chapter2/chapter2_%E5%88%86%E8%AF%8D%E5%99%A8.html)整理。

## 一、分词器是干什么的

大模型不能直接处理“你好”这样的文字，它实际接收的是数字。

分词器主要完成两件事：

```text
原始文本 → 切成 token → 转换成 token ID
```

例如：

```text
"我喜欢人工智能"
→ ["我", "喜欢", "人工智能"]
→ [105, 2087, 6531]
```

反过来，也可以通过这些 ID 恢复出文字，这就是解码。

我觉得这里最重要的一点是：**分词器只负责切分和编号，本身并不理解句子的意思。**真正学习语义的是后面的语言模型。

---

## 2.1 训练分词器

训练一个分词器，大致可以分为四步：

```text
准备语料 → 预分词 → 统计并合并 → 保存词表
```

### 2.1.1 准备语料

分词器的词表是从训练文本中统计出来的，所以语料会直接影响分词效果。

**Tip:**

- 文本类型尽量丰富，例如新闻、小说、代码等。
- 如果要支持多种语言，需要控制各语言的比例。
- 去掉乱码、重复内容和无关信息。
- 姓名、手机号、邮箱等隐私信息需要脱敏。
- 留出少量验证数据，检查训练后的分词效果。

如果中文语料很多、法语语料很少，那么训练出的分词器可能很擅长处理中文，却会把法语切得非常零碎。

### 2.1.2 预分词

预分词就是先对文本进行一次较粗的切分，为后面的统计合并做准备。

课程里介绍了三种方式：

1. 按空格和标点切分

```text
I like Datawhale.
→ ["I", "like", "Datawhale", "."]
```

2. 按 Unicode 字符类别切分

```text
Hello👋，Datawhale成立于2018年
→ ["Hello", "👋", "，", "Datawhale", "成立于", "2018", "年"]
```

3. 按 UTF-8 字节切分

英文通常占一个字节，中文通常占三个字节。字节级切分的优点是几乎可以处理任何文字、符号和 emoji，不容易出现无法编码的字符；缺点是刚开始会切得很碎。

**Tip:**

- Unicode：给每个字符规定一个编号。
- UTF-8：规定这些字符具体如何保存成字节。

### 2.1.3 统计并迭代更新

预分词之后，还要把经常一起出现的片段逐步组合起来。

几种方法可以先这样理解：

| 方法 | 简单理解 |
|---|---|
| BPE | 每次找出现次数最多的相邻片段，然后合并 |
| WordPiece | 不只看次数，还考虑两个片段合在一起是否更合理 |
| Unigram | 先准备一个较大的词表，再逐步删除作用较小的 token |
| SentencePiece | 一个分词工具框架，可以使用 BPE 或 Unigram |

其中，BPE 最直观。例如语料中经常出现：

```text
l o w
l o w e r
```

如果 `l` 和 `o` 经常相邻，就先合并为 `lo`；之后 `lo` 和 `w` 又可能合并为 `low`。不断重复，常见片段就会逐渐成为完整 token。

像 `<PAD>`、`<UNK>`、`<BOS>`、`<EOS>` 这样的特殊 token，一般需要提前保留，不能在训练中被随意拆分或覆盖。

### 2.1.4 保存和检查结果

训练完成后，通常需要保存：

- `vocab`：记录 token 和 ID 的对应关系。
- `merges`：记录 BPE 的合并顺序。
- 有些分词器会把规则统一保存在模型文件中。

保存后还要检查：

- 一段文字会被切成多少个 token。
- 专业词有没有被切得过碎。
- 不同语言的切分效果是否均衡。
- 编码后能否正确解码回原文。

## 2.2 常用的分词方式

### 2.2.1 字符级分词

把文本拆成单个字符。

```text
你好AI
→ ["你", "好", "A", "I"]
```

优点是简单、几乎没有未知字符；缺点是 token 数量很多，而且单个字符包含的信息比较少。

### 2.2.2 字节级分词

将文本转换成 UTF-8 字节，每个字节作为一个 token。

它的覆盖能力最强，中文、英文、emoji 都能处理。但是纯字节分词会让序列很长，所以实际中通常会在字节基础上继续使用 BPE 合并。

### 2.2.3 词级分词

直接把一个完整单词作为 token。

```text
I like apples
→ ["I", "like", "apples"]
```

这样语义比较完整，但词表会非常大。像 `look`、`looks`、`looked` 可能都要分别占一个位置，遇到没见过的新词还会变成 `<UNK>`。

### 2.2.4 BPE 分词

BPE 处在字符级和词级之间：

- 常见词或片段尽量合成一个 token。
- 少见词拆成多个较小的子词。
- 不需要把所有单词都放进词表。

所以它兼顾了词表大小、未知词处理和 token 数量，是目前很常见的选择。

**Tip:** SentencePiece 是工具框架，不是与 BPE 并列的新合并算法；原始 BERT 主要使用 WordPiece，而不是 BPE。

## 2.3 DeepSeek 分词器

课程使用 Hugging Face 加载 DeepSeek Coder 的分词器：

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained(
    "deepseek-ai/deepseek-coder-6.7b-instruct"
)
```

常用操作有三个：

```python
ids = tokenizer.encode(text)
tokens = tokenizer.convert_ids_to_tokens(ids)
result = tokenizer.decode(ids)
```

它们分别表示：

```text
encode：文本 → token ID
convert_ids_to_tokens：token ID → 可观察的 token
decode：token ID → 文本
```

**Tip:** `token ↔ ID` 的映射只表示 token 的内容，并不保存它在句子中的位置。位置信息是后面进入模型时另外处理的。

课程还提到了 `latin-1`。这里可以简单理解为：字节级 BPE 需要临时把每个字节当作一个可操作的“字符”，而 `latin-1` 能让 0～255 的每个字节都一一对应，不容易丢失数据。

## 附录 6：BPE 简易训练代码

这段代码的主要调用顺序是：

```text
准备训练文本
    ↓
用正则进行预分词
    ↓
拆成字符，并添加 </w>
    ↓
统计相邻 token 对的出现次数
    ↓
合并出现次数最多的一对
    ↓
重复多轮，保存 merges
    ↓
使用这些规则进行编码和解码
```

几个关键位置：

- `Counter`：统计词或相邻 token 对出现了多少次。
- `split_graphemes()`：尽量保证组合 emoji 不会被随意拆开。
- `best_pair`：当前出现次数最多的相邻 token 对。
- `merges`：记录每一轮的合并规则。
- `</w>`：表示一个词或预分词片段的结束位置，防止错误地跨边界合并。
- `encode()`：按照训练得到的规则重新合并文本。
- `decode()`：拼接 token，并去掉 `</w>`。

**Tip:** 附录 6 是为了说明 BPE 的合并过程，属于简化的字符/字素簇级 BPE，并不是 DeepSeek 实际使用的完整字节级分词器。训练语料也只有两句话，所以运行成功只能说明代码流程能走通，不能说明训练出了真正可用的分词器。
