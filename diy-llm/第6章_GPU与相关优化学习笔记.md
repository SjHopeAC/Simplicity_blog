# 第 6 章：GPU 与相关优化学习笔记

> 依据 Datawhale 的[《Diy-LLM》第 6 章：GPU 和 GPU 相关的优化](https://datawhalechina.github.io/diy-llm/chapter6/chapter6_%E7%AC%AC%E5%85%AD%E7%AB%A0GPU%E5%92%8CGPU%E7%9B%B8%E5%85%B3%E7%9A%84%E4%BC%98%E5%8C%96.html)整理。

这一章主要回答两个问题：为什么大模型适合在 GPU 上运行，以及为什么“少搬数据”有时比“少做计算”更重要。

---

## 6.1 GPU 的起源

GPU 最初用于图形渲染。画面中的大量像素、顶点都要执行相似的乘加运算，这种任务非常适合并行处理。

深度学习里的矩阵乘法同样由大量重复的乘加运算组成，所以 GPU 后来成为训练神经网络的重要硬件。

### 6.1.1 CPU 和 GPU 的区别

可以先用下面的方式理解：

| CPU | GPU |
|---|---|
| 核心较少但功能复杂 | 计算单元很多，适合并行 |
| 擅长分支、控制和串行逻辑 | 擅长对大量数据执行相似操作 |
| 更关注单个任务延迟 | 更关注整体吞吐量 |

大模型训练并不是只靠 GPU。CPU 仍然负责读取数据、启动任务和调度，GPU 负责执行主要的张量计算。

**Tip:** “CPU 串行、GPU 并行”只是简化说法。CPU 也支持多核和向量计算，GPU 也能处理分支；两者真正的差别在于硬件资源的分配重点不同。

---

## 6.2 GPU 的执行模型

理解 GPU 程序时，经常会遇到四个概念：

```text
Grid → Block → Thread
              ↓
        多个 Thread 组成 Warp
```

- Thread：执行具体指令的基本线程；
- Warp：一组一起执行相同指令的线程，NVIDIA GPU 通常是 32 个；
- Block：一组可以共享片上内存并进行同步的线程；
- SM：流式多处理器，负责调度 Warp，并包含 CUDA Core、Tensor Core、共享内存和寄存器等资源。

一个 GPU 有多个 SM，不同 Block 会被分配到不同 SM 上执行。某个 Warp 等待数据时，SM 可以切换去执行另一个已经准备好的 Warp，用大量并发隐藏访存延迟。

### 分支发散

同一 Warp 内的线程最好执行相同路径。如果一部分线程进入 `if`，另一部分进入 `else`，GPU 往往需要分阶段执行两条路径，暂时屏蔽不属于当前路径的线程。

```c
if (x < 4) {
    A();
} else {
    B();
}
```

这叫分支发散，会降低线程利用率。

## 6.3 GPU 的内存层次

GPU 内存不是只有“显存”一层，而是从大而慢到小而快分成多个层次：

```text
HBM / 全局显存
    ↓
L2 Cache
    ↓
L1 Cache / Shared Memory
    ↓
Registers
```

### 6.3.1 全局内存（HBM）

容量最大，可以存模型权重、激活值等数据，但离计算核心较远。即使带宽很高，相比片上内存仍然慢。

### 6.3.2 L2 Cache

位于 GPU 芯片内部，由所有 SM 共享。经常重复访问的数据如果命中 L2，就不用再次去 HBM 读取。

### 6.3.3 L1 Cache 与共享内存

位于每个 SM 内部，Block 内线程可以通过共享内存交换数据。程序员可以把常用的小块数据提前搬进共享内存，后面重复使用。

### 6.3.4 常量内存

适合保存只读并且会被许多线程同时访问的少量数据。同一 Warp 读取相同常量时，可以利用广播减少重复读取。

### 6.3.5 寄存器

寄存器离计算单元最近，速度最快，但容量很小，并且由单个线程私有。一个线程使用太多寄存器，会减少同一 SM 能同时容纳的 Warp 数量。

内存分层的原因很直接：速度、容量和成本不能同时做到最好。优化的核心，就是让数据尽量停留在离计算单元更近的位置并被重复利用。

个人扩展：可以把 HBM 看成仓库，共享内存看成工作台，寄存器看成手里的工具。每算一步都回仓库拿东西肯定很慢，好的 GPU 程序会一次拿一小批数据到工作台上，连续做完多步再写回去。

## 6.4 TPU 架构

TPU 是 Google 为机器学习设计的专用芯片。GPU 仍需要保留一定通用计算能力，而 TPU 更集中地优化张量和矩阵运算。

TPU 中的矩阵乘法单元与 GPU 的 Tensor Core 在目标上相似：用专门电路高效执行大规模低精度矩阵运算。两者的软件生态和执行方式不同，但都体现了同一个思路——让神经网络中最常见的计算直接匹配硬件。

---

## 6.5 性能扩展趋势

近年的矩阵计算能力增长很快，但显存带宽和设备间通信速度没有同步增长。这就形成了“内存墙”：计算单元越来越快，却经常等数据。

因此，一个操作可能有两种主要瓶颈：

- memory-bound：时间主要花在搬运数据；
- compute-bound：时间主要花在真正计算。

逐元素操作通常计算量少，更容易受内存限制；较大的矩阵乘法能反复利用已经读取的数据，更容易充分使用 Tensor Core。

---

## 6.6 常见性能优化技术

### 6.6.1 避免串行执行

尽量减少 Warp 内不同线程走不同分支，也要让任务数量足够多，使多个 SM 都有工作可做。

### 6.6.2 低精度计算

BF16、FP16、FP8 或 INT8 的数据位数更少，主要带来三方面收益：

- 同样数量的数据占用更少显存；
- 从显存读取的数据量减少；
- Tensor Core 可以用更高吞吐执行低精度矩阵乘法。

但是 softmax、累加和、参数更新等数值敏感环节不一定适合过低精度，所以实际训练通常使用混合精度。

**Tip:** 低精度不是位数越低越好。若模型出现 `nan`、`inf` 或效果明显下降，需要检查缩放、累加精度和硬件支持情况。

### 6.6.3 算子融合

如果几个操作连续处理同一份数据，普通实现可能在每一步都把中间结果写回 HBM，下一步又重新读取。

算子融合把多个操作合并进同一个 Kernel：

```text
读取一次 → 连续完成多个操作 → 写回一次
```

它既减少中间结果读写，也减少 Kernel 启动开销。

### 6.6.4 重计算

反向传播需要使用前向传播的激活值。全部保存会占很多显存，于是可以只保存少量关键节点，在反向时重新计算其余激活值。

这就是重计算或激活检查点：

```text
少存激活值 + 多做一次计算 = 节省显存
```

适合显存紧张、计算资源相对富余的情况。

### 6.6.5 内存合并

同一 Warp 的线程如果访问连续地址，硬件可以把多次访问合并成较少的内存事务。若地址非常分散，就要进行更多次读取。

**Tip:** 关键原则是“同一时刻，Warp 内线程访问连续地址”。究竟表现为按行还是按列，要结合矩阵的实际存储顺序和线程映射判断，不能只记固定结论。

### 6.6.6 分块（Tiling）

矩阵太大，无法整个放入片上内存。Tiling 会把矩阵切成小块：

```text
从 HBM 读取一个块
→ 放入共享内存
→ 在块内完成尽可能多的计算
→ 写回结果
```

这样同一块数据可以被多次复用，减少访问全局显存的次数。分块大小还要适配共享内存容量、矩阵尺寸和 Tensor Core 的计算粒度。

## 6.7 FlashAttention

标准 Attention 会产生一个大小为 `N × N` 的注意力分数矩阵。序列变长时，这个中间矩阵会占用大量显存，并在 HBM 和片上内存之间反复传输。

FlashAttention 的核心不是改变 Attention 的数学结果，而是重新安排计算顺序：

```text
Q、K、V 分块
→ 小块放入片上内存
→ 块内计算 QKᵀ
→ 流式完成 softmax
→ 立即与 V 累积
→ 不保存完整 N×N 中间矩阵
```

### 6.7.1 Online Softmax

普通 softmax 看起来需要先看到一整行数据。Online Softmax 在逐块读取时持续维护当前最大值和指数和，因此不用把完整分数矩阵保存下来，最后仍能得到与标准 softmax 等价的结果（允许正常的浮点误差）。

### 6.7.2 V1、V2、V3 的变化

- V1：通过分块和 Online Softmax 减少 HBM 读写；
- V2：调整任务划分和并行方式，让更多矩阵乘法并行执行；
- V3：进一步利用较新 GPU 的异步搬运、流水线和低精度能力，让取数据和计算尽量重叠。

**Tip:** FlashAttention 通常不会把 Attention 的理论时间复杂度从平方级变成线性级。它主要减少中间结果和显存读写，所以实际运行更快、显存更省。

## 6.8 PagedAttention

自回归推理会为每个请求保存 KV Cache。如果按最大序列长度提前分配一整块连续显存，而请求最后只生成很少的 token，就会浪费大量空间。不同请求不断创建和结束，还可能产生很多零散空闲块。

PagedAttention 借用了操作系统分页的思路：

```text
逻辑 KV 序列
→ 切成固定大小的 Page
→ 通过页表映射到不连续的物理显存
```

请求生成更多 token 时再按需分配新 Page，不需要一开始占满最大长度。

### FlashAttention 与 PagedAttention 的区别

| 技术 | 主要解决的问题 |
|---|---|
| FlashAttention | 单次 Attention 如何少搬数据、算得更快 |
| PagedAttention | 多个推理请求的 KV Cache 如何少浪费显存 |

前者更偏算子实现，后者更偏推理系统的内存管理，两者可以同时使用。

个人扩展：如果训练长序列时 Attention 显存过大，先想到 FlashAttention；如果部署服务时并发请求多、KV Cache 浪费严重，才更应该想到 PagedAttention。

## 6.9 国产 AI 芯片简介

课程介绍了沐曦、昆仑芯、壁仞、华为昇腾、寒武纪、海光、摩尔线程和平头哥等国内厂商。学习这一节时，不必只比较一个峰值算力数字，还要一起看：

- 支持哪些数据精度和模型结构；
- 显存容量和显存带宽；
- 多卡互联能力；
- 编译器、算子库和框架适配；
- 实际供货、稳定性和开发工具；
- 目标模型能否低成本迁移。

**Tip:** 芯片型号、量产计划、价格和软件兼容性变化很快。课程中的厂商数据适合了解格局，真正选型时要重新查看厂商官方文档，并用目标模型做实测。

## 个人扩展：实际优化时怎么判断

可以先从现象出发：

| 现象 | 优先检查 |
|---|---|
| 直接 OOM | batch、序列长度、精度、激活值、重计算 |
| GPU 经常空闲 | 数据加载、CPU 到 GPU 传输、任务规模 |
| 显存占用不高但速度慢 | 是否 memory-bound、算子太碎、缺少融合 |
| 长序列 Attention 很慢 | FlashAttention、序列长度和注意力方式 |
| 推理并发低、KV Cache 浪费 | PagedAttention、批处理和缓存管理 |

优化前最好先做性能分析，找到真正占时间或显存的部分。只凭经验更换精度、增加并行或改写 Kernel，可能没有收益，甚至会让程序更慢。
